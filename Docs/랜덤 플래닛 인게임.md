## 1. One-line concept
> "캐릭터 자체가 가챠인 로그라이트 핵앤슬래시 — 매번 랜덤 스탯·특성으로 태어난 캐릭터가 사이드뷰 전장에서 수동 조작 전투로 웨이브를 돌파하고, 죽으면 영구 삭제되지만 계정은 성장하는 런 기반 게임."

## 2. Key decisions (immutable baseline)

| Item | Decision | Notes |
|---|---|---|

## 3. Core loop (one session)

```
캐릭터 생성 (스탯 4종 랜덤 분배 + 특성 1개 랜덤 배정, 축소 풀 5~10종)
  → 전장 입장
  → 좌우에서 몬스터 웨이브 등장 → 수동 조작(이동/점프 + 평타 + 스킬)으로 처치
  → 처치 시 스탯 구슬 / 경험치 획득
  → 레벨업 시 3택1 이능 팝업 (스탯 재분배 / 추가 스탯 / 특성 변경)
  → (일정 웨이브 이후) 미니보스 등장
  → 미니보스 처치 → 클리어  또는  체력 0 → 캐릭터 영구 사망
  → ENDING 화면 (도달 레벨·처치 수·생존 시간 기록) → 재시작(새 캐릭터 생성)
```

## 4. Core systems

- **플레이어**: 힘(STR)/민첩(DEX)/지능(INT)/행운(LUK) 4종 랜덤 분배(원 기획 8-1 계수 축소 적용). 특성은 MVP 전용 축소 풀(5~10종, good/bad 성격만 섞어서 선별 — Hidden/Gamble 세분화는 이연). 조작: 방향키 이동, 점프, 공격키(평타), 스킬키 1개(쿨다운 기반).
- **적**: 좌우 포털에서 기본 몬스터 웨이브 스폰(1~2종으로 축소), 일정 웨이브 후 미니보스 1종 등장.
- **성장**: 레벨(MVP는 최대 5~10, 원 기획 21은 이연), 처치 시 스탯 구슬·경험치 드랍, 레벨업마다 이능 3택1 팝업.
- **보상/난이도**: MVP는 난이도 단일 구간(하급만). 4단계 난이도 스케일(5-1)은 이연.
- **UI**: HP/MP/경험치 HUD, 레벨업 이능 선택 팝업, ENDING 화면(간단 기록).
- **공격대 편성**: 캐릭터 선택창에서 플레이어블 1개를 고른 뒤, 나머지 보유 캐릭터 중 최대 2개를 링크로 지정. 링크 캐릭터는 15레벨 이상일 때만 **자기 특성에 내장된 링크 패시브**(별도로 뽑는 게 아니라 특성 하나당 항상 세트로 붙어있는 두 번째 효과 — 정확한 메커니즘·전체 114종 매핑은 `랜덤 플래닛 전체 기획서.md` §2-6/부록 D 참고)가 적용되는 것으로 설계되어 있으나, 실제 효과 연결은 특성/전투 시스템(Phase 3+)이 갖춰진 뒤 진행 — 지금은 편성 UI와 선택 데이터 구조만 구현.
- **사망/재시작**: 체력 0 → 캐릭터 영구 삭제 + ENDING 화면 → 새 캐릭터 생성 화면으로 복귀. 계정 영구 재화·메타강화는 이연(§8).

## 6. Roadmap (Phases)

### Phase 0 — "캐릭터 선택창" (유저 요청으로 M2에서 앞당김, 2026-07-13 메이플 클래식 스타일로 재설계 → 같은 날 저녁 `.ui` 방식 전면 폐기하고 `choice_map` 월드 엔티티 방식으로 재작성)

> ⚠️ **아키텍처 히스토리**: 이 Phase는 하루 동안 두 번 크게 재설계됐다. (1) 오전~오후: `.ui` 오버레이(화살표 순환 + 팝업) 방식으로 구현·검증 완료. (2) 저녁: 유저가 "UI가 아니라 실제 `choice_map` 위에 버튼이 있는 방식으로, 메이플 캐릭터 선택창처럼"이라고 명시적으로 요청 → `.ui` 파일 전부 삭제하고 **월드 엔티티(`TouchReceiveComponent`+`TextRendererComponent`) 방식**으로 전면 재작성. 아래 체크리스트는 **현재(월드 엔티티) 아키텍처 기준**이다 — 폐기된 `.ui` 버전의 세부 구현 이력은 §9 리비전 로그에만 남아있다.

- ✅ **선택 상호작용 방식 확정**: 화살표로 1명씩 순환하는 방식을 버리고, **6명 전원 동시 노출 + 원하는 캐릭터(또는 빈 슬롯) 직접 클릭** 방식으로 확정(유저가 AskUserQuestion으로 확인, "실제 메이플 캐릭터 선택창과 동일 방식"을 추천안으로 선택). 화살표 자체가 사라지면서 지난 세션에 발견된 "좌우 화살표 버튼 클릭 미반응" 버그도 함께 해소됨(원인 규명은 안 했지만 더 이상 해당 코드 경로가 없음).
- ✅ **`CharacterStandee.model` 확장** — 기존 실루엣+Glow 구조에 `TouchReceiveComponent`(AutoFitToSize) 추가(클릭 감지) + `NameTag` 자식(`TextRendererComponent`, 빈 슬롯="+", 채워진 슬롯="Lv.N") 추가. `MapBuilder.placeModel` 재실행으로 기존 6개 배치(Standee1~6, choice_map)에 안전하게 동기화(위치 보존, Glow/NameTag 자동 미러링).
- ✅ **`WorldButton.model` 신규 작성** — 재사용 가능한 월드 버튼 템플릿(`SpriteRendererComponent`+`TouchReceiveComponent`+`Label` 자식 텍스트). `BtnAction`(빈 슬롯일 때만 노출되는 순수 "생성" 버튼 — 최초엔 생성/선택 토글이었다가 아래 카드 UI 도입으로 토글 제거)·`BtnDelete` 2개 인스턴스를 `choice_map`에 배치.
- ✅ **월드 텍스트 2종** (`TitleText`/`CountText`) — `MapBuilder.empty()`+`upsertComponent(TextRendererComponent)`로 `choice_map`에 직접 배치(타이틀/일일 생성 카운트). 슬롯 상세 스탯 표시는 최초엔 3번째 월드 텍스트(`DetailText`)였다가, 아래 카드 UI 도입 후 `DetailText`는 삭제하고 카드로 역할 이전.
- ✅ **`RootDesk/MyDesk/CharacterSelect/CharacterSelectStageController.mlua` 신규 작성** — `choice_map` 맵 루트 엔티티에 붙는 `@Component`(map-scoped, 기존처럼 UI 스크립트가 아님). 6개 스탠디 터치(`TouchEvent`, 클로저로 인덱스 캡처) + BtnAction/BtnDelete 터치 wiring, `RefreshStage()`가 매번 glow/nametag/detail text/버튼 라벨/카운트를 전부 갱신. 스탠디 자식(Glow/NameTag)은 UUID property 주입이 아니라 `GetChildByName()`으로 런타임 조회(지난 세션 겪었던 "자식 엔티티 UUID 불일치" 부류의 버그를 원천 차단).
- ✅ **기존 `.ui` 시스템 삭제** — `ui/CharacterSelectGroup.ui`, `ui/CharacterCreateGroup.ui`, `RootDesk/MyDesk/UI/CharacterSelectController.mlua`(구), `RootDesk/MyDesk/UI/CharacterCreateController.mlua` 전부 제거(builder 미지원 삭제라 `.ui`는 node `fs.unlinkSync`로 직접 삭제, `.mlua`/`.codeblock`은 `rm`).
- ✅ **런타임 검증 완료(2026-07-13 저녁)** — `choice_map`이 아직 월드 시작 맵이 아니라(아래 블로커 참고) 정상적인 `play`만으로는 진입이 안 되어, **`maker_execute_script`로 서버 컨텍스트에서 로컬 플레이어를 `_TeleportService:TeleportToMapPosition(...)`으로 `choice_map`에 강제 이동시켜 검증**(테스트 전용 우회 — 영구 조치 아님). 확인된 것: `standee1~6`/`btnAction`/`btnDelete` 전부 `valid=true`(지난 세션 버그였던 "월드 시작 맵 미지정 → 엔티티 미로드" 가설이 정확했음을 재확인), 스탠디 클릭 → `OnStandeeTouched` 로그 + 선택 glow 이동, `생성` 버튼 클릭 → 랜덤 스탯 즉시 커밋 + `DetailText`/`NameTag`/카운트 갱신, 같은 버튼이 채워진 슬롯에서 "선택"으로 라벨 전환 + 클릭 시 로그, `삭제` 버튼 → 슬롯 초기화 + 카운트 환급까지 로그·스크린샷으로 전부 확인. 빌드 로그 0 error.
- ✅ **시각 튜닝 1차** — `TextRendererComponent.FontSize`가 월드 유닛과 무관한 별도 스케일임을 스크린샷 3회 반복으로 실측(0.6→거의 안 보임, 40→화면을 뒤덮음, 최종 2.6~6 범위로 수렴). 텍스트/맵 실제 `SortingLayer`(맵은 `Layer1`인데 초기엔 `MapLayer0`로 잘못 맞춰서 겹침 순서가 어긋났던 것) 정정 + 흰 배경(구름) 대비를 위해 타이틀/카운트/디테일 텍스트에 아웃라인 추가.
- ✅ **월드 시작 맵을 `choice_map`으로 지정 (유저 작업 완료, 2026-07-13)** — 유저가 Maker에서 직접 설정. `maker_get_current_map`으로 `play` 진입 시 실제 로드 맵이 `choice_map`으로 바뀐 것 재확인. 이 시점부터 `maker_execute_script` 강제 텔레포트 없이 정상 `play`만으로 무대 검증 가능해짐.
- ✅ **캐릭터 생성 시 슬롯에 실제 아바타 채우기** — 유저 요청("1~6번 슬롯에 현재 플레이어 아바타 또는 메이플월드 기본 아바타를 랜덤으로 돌려서 채워진 형식으로"). `msw-avatar`+`msw-search` 스킬로 구현: **기본 바디**(`GET /v3/avatars/defaults`) 고정 + **헤어/얼굴/코트/바지/신발**은 `searchAvatarItems`로 각 슬롯당 6종씩 확보한 랜덤 풀에서 매 생성마다 하나씩 추첨(실시간 라이브 플레이어 아바타 복제가 아니라 "메이플월드 기본 제공 아바타 랜덤 조합" 쪽으로 결정 — 6칸이 서로 다른 룩으로 보이는 다양성 + 가챠 테마 적합성 고려, AI가 판단해 진행하고 근거를 유저에게 보고). 구현: `CharacterStandee.model`에 `AvatarBody` 자식 신설(`StateComponent`+`AvatarStateAnimationComponent`+`AvatarRendererComponent`+`CostumeManagerComponent`, `IsLegacy=false` 양쪽 다 설정, `UseCustomEquipOnly=true`로 실제 유저 계정 코스튬은 무시) — 처음엔 루트 엔티티에 붙였다가 아바타가 발판 위로 붕 뜨는 현상 발견(아바타는 발밑 피벗인데 루트 Transform은 실루엣 스프라이트의 중앙 피벗 보정용 +0.85 오프셋이 걸려 있었음) → 자식으로 분리하고 로컬 Y `-0.85`로 상쇄해 발판 정렬 해결. 빈 슬롯="+" 실루엣 유지, 채워진 슬롯=실루엣 숨김+아바타 표시로 `RefreshStage()`에서 토글. 서로 다른 슬롯 2곳에 생성해 각기 다른 헤어/의상 조합으로 렌더링되는 것까지 스크린샷 확인 완료.
- ✅ **아바타 랜덤 룩에 스킨톤(성별 대용) 추가 + "다음 캐릭터 생성 안 됨" 제보 조사** — 유저가 "성별과 헤어 얼굴 이런거 다 랜덤으로"라고 요청. 이 아바타 에셋 인덱스에는 성별=별도 체형 슬롯이 없고 `Body` 슬롯 자체가 스킨톤 변형이라는 걸 확인(`male body`/`female body`로 검색해도 동일한 피부톤 결과만 나옴) — 그래서 스킨톤 6종 랜덤 풀을 추가하는 것으로 구현(유저에게 이 기술적 한계 보고). "생성 후 다음 캐릭터를 못 만든다"는 제보는 실제로 재현 안 됨 — 슬롯 1→4→5 연속 생성을 로그로 3회 검증 성공. 유력한 원인은 버그가 아니라 UX: 기존엔 같은 버튼이 빈 슬롯="생성"/채워진 슬롯="선택"으로 토글돼서, 새 슬롯을 먼저 클릭하지 않고 같은 버튼을 다시 누르면 아무 반응이 없어 "고장났다"고 느꼈을 것으로 추정 — 아래 카드 UI 도입으로 이 토글 자체를 없애 재발 방지.
- ✅ **캐릭터 선택 시 레벨/특성/스탯 카드 UI 팝업 추가** — 유저 요청("캐릭터를 선택하면 레벨/스탯/특성이 나오는 UI가 나오고, 맵 전환은 없이, 카드 사이즈로, 그 다음 PLAY 버튼"). 신규 `ui/CharacterCardGroup.ui`(420×480 카드 패널, 타이틀/Lv./특성/스탯 텍스트 + PLAY·닫기(X) 버튼, `DefaultShow=false`) + `RootDesk/MyDesk/CharacterSelect/CharacterCardController.mlua`(카드 표시 스크립트, `ShowCard`/`HideCard` 메서드를 `CharacterSelectStageController.RefreshStage()`에서 호출). 빈 슬롯 선택 시 자동으로 닫힘(월드 "생성" 버튼이 대신 노출).
